**datasets.py -- Add `load_gsm_symbolic_contamination()` function:**

Add a new function `load_gsm_symbolic_contamination(n_per_type=100, seed=137, fresh_instance_id=0)` that:
1. Loads `apple/GSM-Symbolic` HuggingFace dataset (`main` config, `test` split)
2. Groups rows by template `id` field (100 templates, 50 instances each)
3. For each template:
   - Creates a "fresh" problem using instance `fresh_instance_id` (the generated variant with different numbers). problem_id format: `gsm_symbolic_{template_id}_fresh`. Set `is_fresh=True`.
   - Creates an "original" problem using `original_question` and `original_answer` fields (the GSM8K text the model may have been trained on). problem_id format: `gsm_symbolic_{template_id}_original`. Set `is_fresh=False`.
4. Parses answers using the existing `####` separator logic (split on `####`, strip, try int then float)
5. Applies verification format (Yes/No) same as existing `load_gsm_symbolic()`: for each problem, create both a Yes item (correct answer presented) and a No item (distractor presented via `_generate_distractor()`)
6. Applies `_balance_and_sample()` separately for fresh and original items, sampling `n_per_type` from each
7. Returns combined list with both fresh and original items, each having all standard fields PLUS `is_fresh: bool`
8. The existing `load_gsm_symbolic()` function stays untouched (backward compatible)

Also update `load_dataset_by_name()` to support a `"gsm_symbolic_contamination"` name that dispatches to the new function with appropriate signature.

**multiprocess.py -- Add `run_parallel_isolated()` function:**

Add a new function `run_parallel_isolated(worker_fn, items, gpu_ids, cfg)` that:
1. Uses `split_work()` to divide items across workers
2. Deterministically shuffles items before splitting (using `cfg.seed` as shuffle seed) so no single GPU gets all "hard" problems
3. Creates one `mp.Process` per GPU (NOT `mp.spawn`)
4. Each process calls a wrapper that: sets CUDA device, calls `worker_fn(rank, gpu_id, chunk, cfg)`, catches all exceptions and logs them
5. Starts all processes, then joins all processes
6. After join, checks `p.exitcode` for each. Collects failed workers (rank, gpu_id, exitcode).
7. Logs ERROR for each failed worker with its exitcode
8. Returns list of failed worker tuples for caller inspection
9. For single GPU (len(gpu_ids) == 1), still uses mp.Process (not in-process) for consistency with multi-GPU behavior -- but add a comment noting the caller can use the existing `run_parallel()` for debuggable in-process single-GPU runs

The existing `run_parallel()` function stays untouched (backward compatible).

Do NOT use mp.spawn anywhere in the new function. The whole point is fault isolation.

**storage.py -- Add path helpers for decoupled trace/activation layout:**

Add these functions (keep all existing functions untouched):

1. `get_trace_json_path(traces_dir, dataset_name, problem_id, trace_idx)` -> str
   Format: `{traces_dir}/valid/{dataset_name}/{problem_id}/trace_{trace_idx:02d}.json`
   This is for generation output (JSON files).

2. `get_failed_trace_json_path(traces_dir, dataset_name, problem_id, trace_idx)` -> str
   Format: `{traces_dir}/failed/{dataset_name}/{problem_id}/trace_{trace_idx:02d}.json`
   This is for quarantined traces.

3. `get_activation_path(activations_dir, dataset_name, problem_id, trace_idx)` -> str
   Format: `{activations_dir}/{dataset_name}/{problem_id}/trace_{trace_idx:02d}.safetensors`
   This is for activation capture output.

4. `write_trace_json(data, path)` -> None
   Atomic write: create parent dirs, write to a tempfile in same directory (using `tempfile.mkstemp`), then `os.rename()` for POSIX atomic rename. On error, unlink the temp file and re-raise. Import `tempfile` at top of file.

5. `derive_trace_seed(problem_id, trace_index)` -> int
   Hash-based: `int(hashlib.md5(f"{problem_id}_{trace_index}".encode()).hexdigest(), 16) % (2**32)`. If result is 42, return 43. Import `hashlib` at top of file.
