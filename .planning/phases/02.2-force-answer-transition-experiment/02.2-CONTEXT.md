# Phase 2.2: Force-Answer Transition Experiment - Context

**Gathered:** 2026-02-19
**Status:** Ready for planning

<domain>
## Phase Boundary

Exploratory experiment to determine whether Qwen3-8B exhibits a phase transition during chain-of-thought reasoning — a point where the model shifts from "not knowing" to "reliably knowing" the correct answer. Tests this by truncating the thinking trace at evenly-spaced positions, force-closing the `<think>` block with `</think>\n`, letting the model generate, and measuring correctness + logit probabilities. Small pilot (~50 traces), single GPU. Visualization-first — let the data speak, no formal transition point definition needed yet.

</domain>

<decisions>
## Implementation Decisions

### Forcing method
- Truncate thinking trace at probe position t, append `</think>\n` to force-close the thinking block
- Let the model freely generate 10-20 tokens (short — just enough to capture the answer)
- Use KV-cache reuse for efficiency: forward pass to position t, then feed `</think>\n` and generate from the cached state
- Track both the generated answer AND the logit probabilities of Rho/Tau at the generation step

### Answer extraction & matching
- **Dual matching**: check both token-level (first Rho/Tau token in generated output) and string-level (decoded text contains answer string). Flag disagreements for manual inspection.
- **No-answer category**: if model produces no valid answer (garbage, continues reasoning, EOS), record as "no_answer" — a separate category from incorrect. Must be easy to reclassify as "incorrect" later for analysis flexibility.
- **Logit scope**: record only Rho and Tau logit probabilities (not full top-k). Minimal and directly relevant.

### Probe point spacing
- **Even spacing**: ~20 points evenly distributed within the thinking block (between `<think>` and `</think>` tokens)
- No filtering by trace length — random sample, the length distribution itself is data
- Future iterations may try denser-near-boundaries or fixed-stride, but even spacing is the priority

### Trace selection for pilot
- ~50 traces total, equal split across datasets (~17 each for GSM-Symbolic, FOLIO, StrategyQA)
- **Mostly correct traces (~40), some incorrect (~10)**: focus on traces where the model CAN get it right, but include some incorrect ones to spot over-thinking patterns
- Random sample within each dataset, no length filtering
- **GSM-Symbolic: include both fresh AND original (potentially contaminated) instances** — compare whether memorization affects transition dynamics

### Visualization & analysis
- **No formal transition point definition** — this is exploratory. Plot the data and visually inspect.
- **Aggregate accuracy plot**: mean accuracy at each normalized position (0-1 x-axis) with 95% confidence band
- **Probability plot**: mean probability of correct answer token at each position — shown side-by-side with accuracy plot. Probability may show a smoother transition than binary accuracy.
- **Per-dataset overlay**: all 3 datasets on one plot, color-coded, for direct comparison of transition dynamics
- Auto-generate plots (matplotlib/seaborn) as part of the script — no separate notebook needed

### Result structure & outputs
- Results saved under `$EXP_DIR/force_answer/`
- **Single CSV/parquet** for all traces: columns include trace_id, dataset, problem_id, probe_position, normalized_position, correct (bool), no_answer (bool), rho_prob, tau_prob, ground_truth, is_fresh (for GSM)
- **Do NOT store generated text** — just metrics. Can re-run specific positions if inspection needed.
- **Auto-generated plots** saved as PNG alongside the CSV

### Claude's Discretion
- Exact matplotlib style/colors for plots
- How to handle very short traces where 20 probe points would be too dense (e.g., minimum spacing between points)
- CSV vs parquet format choice
- Whether to use `model.generate()` or manual token-by-token generation for the forced answer

</decisions>

<specifics>
## Specific Ideas

- The core insight being tested: "Is there a moment during thinking where the model flips from guessing to knowing?" If the accuracy curve shows a sharp S-curve, that's strong evidence for a phase transition.
- Comparing fresh vs original GSM-Symbolic traces could reveal whether memorized problems show earlier/sharper transitions — a contamination diagnostic.
- The "no_answer" category is interesting in itself: if early positions produce "no answer" while later positions produce wrong answers before getting right ones, that tells a story about the model's reasoning process.

</specifics>

<deferred>
## Deferred Ideas

- Denser-near-boundaries probe spacing — try after initial results reveal where transitions happen
- Fixed-stride spacing (every N tokens) — alternative to even spacing
- Storing generated text at each probe point — can add later if manual inspection is needed
- Jupyter notebook for interactive exploration — can create if the auto-plots aren't sufficient
- Formal transition point detection algorithms (threshold crossing, inflection point) — defer until we see the shape of the curves

</deferred>
