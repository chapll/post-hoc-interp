**Function: `load_all_seed_traces(traces_dir, correct_problems, cfg)`**
Load all 20 traces (indices 0-19) for each correct problem.

For each problem in correct_problems:
  - Extract problem_id and dataset from the problem dict
  - For trace_index in range(0, cfg.cross_seed.total_seeds):  # 0-19
    - Build path: `get_trace_json_path(traces_dir, dataset, problem_id, trace_index)` (import from src.storage)
    - If file does not exist, log warning and skip
    - Read the JSON file
    - Check single-think-block filter: `meta["has_think"] and meta["num_think_blocks"] == 1`
    - If passes filter, create a trace_data dict matching the format expected by `probe_trace()`:
      ```python
      {
          "trace_path": trace_path,
          "token_ids": trace["token_ids"],
          "metadata": trace["metadata"],
          "is_correct": True,  # all are originally correct
          "dataset": dataset,
          "seed_index": trace_index,    # NEW: 0-19
          "trace_index": trace_index,   # NEW: 0-19
      }
      ```
    - If fails filter, log and skip (count skipped per problem)
  - Log: "Problem {pid}: {n_valid}/{total_seeds} valid traces"

Return: list of all trace_data dicts (flat list, not grouped by problem)

**Function: `probe_trace_with_seed(raw_model, tokenizer, trace_data, cfg_shim, device)`**
Wrapper around `probe_trace()` that adds seed_index and trace_index to each result row.

CRITICAL: This function receives `cfg_shim` (NOT the full cross_seed config). The `cfg_shim` is a minimal OmegaConf dict with a `force_answer` key, which is what `probe_trace()` expects (it accesses `cfg.force_answer`). Passing the full cross_seed config would cause `ConfigAttributeError` because it has no `force_answer` key.

The caller (`_worker`) builds `cfg_shim` once and passes it to every call:
  ```python
  from omegaconf import OmegaConf
  cfg_shim = OmegaConf.create({
      "force_answer": {
          "num_probes": cfg.cross_seed.num_probes,
          "min_probe_spacing": cfg.cross_seed.min_probe_spacing,
          "max_new_tokens": cfg.cross_seed.max_new_tokens,
      }
  })
  ```

- Call `probe_trace(raw_model, tokenizer, trace_data, cfg_shim, device)` -- `cfg_shim` is passed through directly, NOT the full `cfg`.
- For each row in the returned results:
  - Add `row["seed_index"] = trace_data["seed_index"]`
  - Add `row["trace_index"] = trace_data["trace_index"]`
  - Override `row["trace_id"] = trace_data["metadata"]["problem_id"]` -- but note that probe_trace already sets trace_id to metadata["problem_id"]. However, for traces with _cfga/_cfgb suffixes in problem_id, the trace_id needs to be the SAME as the problem_id. This is already correct since the problem_id in metadata is the full ID including _cfga suffix.
- Return the modified results list.

WAIT -- Important clarification: The Phase 2.2 selection works on the cfga/cfgb problem IDs (each config variant is a separate "problem" in the trace directory). The cross_seed generation (Plan 01) generates traces 3-19 for these same problem_ids (which include _cfga/_cfgb suffixes). So when we load all 20 traces, the problem_id already includes the config suffix. This is correct -- we treat each (base_problem, config) pair as a distinct "problem" for the cross-seed analysis.
