  <action>
    Create multiprocess.py with the following.

    **`split_work(items: list, num_workers: int) -> list[list]`:**
    - Splits a list of items into num_workers roughly-equal chunks
    - Last chunk may be slightly smaller/larger
    - Returns list of lists

    **`run_parallel(worker_fn: Callable, items: list, gpu_ids: list[int], cfg: DictConfig) -> None`:**
    - The main entry point for parallel execution
    - If len(gpu_ids) == 1: run worker_fn directly in the current process (no spawning). This avoids multiprocessing overhead for single-GPU use and simplifies debugging.
    - If len(gpu_ids) > 1: use torch.multiprocessing.spawn
    - Splits items into len(gpu_ids) chunks using split_work
    - Worker function signature: `worker_fn(rank: int, gpu_id: int, items: list, cfg: DictConfig) -> None`
    - The wrapper passed to mp.spawn should:
      1. Extract gpu_id from gpu_ids[rank]
      2. Call torch.cuda.set_device(gpu_id) BEFORE any CUDA operations
      3. Call the user-provided worker_fn with (rank, gpu_id, items_chunk, cfg)
    - mp.spawn args: nprocs=len(gpu_ids), join=True
    - Any exception in any worker should propagate to main process

    **Important design decisions:**
    - worker_fn is responsible for loading its own model (via load_model(gpu_id)). This module does NOT load models.
    - worker_fn is responsible for processing its items chunk and saving results.
    - This module only handles: work splitting, process spawning, GPU assignment, error propagation.
    - Single-GPU path runs in-process (not spawned) for simplicity and debuggability.
    - Do NOT use DDP, FSDP, or any distributed training primitives. This is data-parallel inference only.
    - Do NOT use mp.Process directly -- use mp.spawn which handles start method correctly.

    **Error handling:**
    - If mp.spawn raises, re-raise with clear message about which rank failed
    - Log start/end of each worker with rank and gpu_id
  </action>
