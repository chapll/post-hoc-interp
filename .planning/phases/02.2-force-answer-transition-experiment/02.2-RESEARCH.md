## Summary

This phase implements a force-answer experiment: truncate the model's thinking trace at ~20 probe positions, append `</think>\n` to force-close the thinking block, let the model generate a short answer, and measure whether it gets the right answer and what the logit probabilities of the correct answer token are. The data from ~50 traces across 3 datasets is then plotted as accuracy-vs-position and probability-vs-position curves to visually detect phase transitions in reasoning.

Research covered five domains: (1) KV cache mechanics for efficient truncate-and-generate, (2) trace JSON format and loading, (3) Rho/Tau token identification and matching, (4) existing codebase infrastructure for reuse, and (5) plotting patterns. All critical findings are verified against the actual codebase and tokenizer (HIGH confidence).

**Primary recommendation:** Use the KV cache prefill-then-crop-descending approach for efficiency. Process probes from rightmost to leftmost within each trace, reusing a single prefilled cache without deepcopy. Use `model.generate()` with `return_dict_in_generate=True, output_logits=True` to capture logits from the first generated token. Use parquet (not CSV) for results storage.

### Pattern 1: Prefill-then-Crop-Descending (KV Cache Reuse)

**What:** Prefill the KV cache with the full thinking trace, then process probe points from rightmost to leftmost, cropping the cache successively. No deepcopy needed.

**When to use:** Processing multiple probe points for the same trace (our exact use case).

**Why descending order:** `DynamicCache.crop(n)` truncates to the first `n` positions. If we process probes right-to-left (position 19 before 18 before 17...), each crop only needs to remove positions from the end. After `model.generate()` appends tokens to the cache, the next `crop()` removes both the generated tokens AND steps back to the next probe position. The first `n` positions always contain the original prefilled values.

**Example:**
```python
# Source: Verified against transformers 5.0.0 DynamicCache API
import copy
import torch
from transformers import DynamicCache

def probe_trace(model, tokenizer, trace_token_ids, think_start, think_end, probe_positions, device):
    """Run force-answer probes at multiple positions using KV cache reuse.

    Args:
        model: nnsight LanguageModel wrapping Qwen3-8B
        tokenizer: model tokenizer
        trace_token_ids: full token ID list from the trace JSON
        think_start: index of <think> token
        think_end: index of </think> token
        probe_positions: list of absolute token positions within the thinking block
        device: torch device

    Returns:
        list of result dicts, one per probe position
    """
    raw_model = model._model  # raw HuggingFace model

    # Tokens up to and including <think>
    prefix_ids = trace_token_ids[:think_start + 1]
    # All thinking content tokens (between <think> and </think>, exclusive)
    think_content = trace_token_ids[think_start + 1 : think_end]

    # Build full input: prefix + all thinking content
    full_input_ids = prefix_ids + think_content
    full_tensor = torch.tensor([full_input_ids], dtype=torch.long, device=device)

    # Prefill: forward pass to populate KV cache for all thinking tokens
    cache = DynamicCache(config=raw_model.config)
    with torch.no_grad():
        outputs = raw_model(
            input_ids=full_tensor,
            past_key_values=cache,
            use_cache=True,
        )
    # cache now contains KV for all len(full_input_ids) positions

    # Close tokens: </think> + \n
    close_token_ids = [151668, 198]  # </think>, \n
    close_tensor = torch.tensor([close_token_ids], dtype=torch.long, device=device)

    results = []

    # Process probes in DESCENDING order (rightmost first)
    for pos in sorted(probe_positions, reverse=True):
        # Crop cache to prefix + thinking content up to position pos
        # pos is relative to think_content, so absolute cache length is:
        cache_length = len(prefix_ids) + pos
        cache.crop(cache_length)

        # Build full input_ids for generate (prefix + think[:pos] + close_tokens)
        input_for_generate = full_input_ids[:cache_length] + close_token_ids
        input_tensor = torch.tensor([input_for_generate], dtype=torch.long, device=device)
        attention_mask = torch.ones_like(input_tensor)

        # Generate with cached prefix
        with torch.no_grad():
            gen_output = raw_model.generate(
                input_ids=input_tensor,
                attention_mask=attention_mask,
                past_key_values=copy.deepcopy(cache),  # deepcopy so cache isn't mutated
                max_new_tokens=15,
                do_sample=False,  # greedy for reproducibility
                return_dict_in_generate=True,
                output_logits=True,
            )

        # Extract results from gen_output
        generated_ids = gen_output.sequences[0, len(input_for_generate):].tolist()
        first_logits = gen_output.logits[0][0]  # logits at first generated token

        results.append({
            'probe_position': pos,
            'generated_ids': generated_ids,
            'first_logits': first_logits,
        })

    return results
```

**IMPORTANT UPDATE on the descending approach:** After further analysis, the descending-crop-without-deepcopy approach has a subtlety. When `model.generate()` is called with `past_key_values=cache`, it modifies the cache in-place by appending KV entries for the close tokens and generated tokens. Subsequent `crop()` calls would truncate back, BUT the KV values at positions below the crop point might be affected if attention computations during generation modified internal state. To be safe, use `copy.deepcopy(cache)` when passing to generate, as shown in the example above. The benefit of descending order is that we only need to deepcopy the _cropped_ cache (smaller), not the full one.

### Pattern 2: Simple Per-Probe Forward Pass (Fallback)

**What:** For each probe point, construct the truncated input and call `model.generate()` from scratch. No cache management needed.

**When to use:** If KV cache approach has issues, or for simplicity during initial development.

**Example:**
```python
def probe_simple(raw_model, trace_token_ids, think_start, probe_position, close_token_ids, device):
    """Simple approach: build input from scratch for each probe."""
    input_ids = trace_token_ids[:think_start + 1 + probe_position] + close_token_ids
    input_tensor = torch.tensor([input_ids], dtype=torch.long, device=device)
    attention_mask = torch.ones_like(input_tensor)

    with torch.no_grad():
        gen_output = raw_model.generate(
            input_ids=input_tensor,
            attention_mask=attention_mask,
            max_new_tokens=15,
            do_sample=False,
            return_dict_in_generate=True,
            output_logits=True,
        )
    return gen_output
```

**Time estimate:** ~17 minutes for 1000 probes (50 traces x 20 probes). Acceptable for a pilot.

### Pattern 3: Answer Extraction with Dual Matching

**What:** Extract the model's answer from generated tokens using both token-level and string-level matching.

**Example:**
```python
# Rho token IDs: [49, 6161] (tokenizes as "R" + "ho")
# Tau token ID: [92713] (single token)
RHO_TOKEN_IDS = [49, 6161]
TAU_TOKEN_ID = 92713

def extract_answer(generated_ids, generated_text, valid_token, invalid_token):
    """Dual matching: token-level and string-level answer extraction.

    Args:
        generated_ids: list of generated token IDs (after the forced </think>\n)
        generated_text: decoded string of generated tokens
        valid_token: "Rho" or "Tau" (the token meaning "correct")
        invalid_token: "Tau" or "Rho" (the token meaning "incorrect")

    Returns:
        dict with answer, method, agreement fields
    """
    # Token-level: find first Rho or Tau token in generated output
    token_answer = None
    for tid in generated_ids:
        if tid == TAU_TOKEN_ID:
            token_answer = "Tau"
            break
        if tid == RHO_TOKEN_IDS[0]:  # "R" - check if followed by "ho"
            idx = generated_ids.index(tid)
            if idx + 1 < len(generated_ids) and generated_ids[idx + 1] == RHO_TOKEN_IDS[1]:
                token_answer = "Rho"
                break

    # String-level: check decoded text
    string_answer = None
    text_lower = generated_text.lower().strip()
    if "rho" in text_lower:
        string_answer = "Rho"
    if "tau" in text_lower:
        # If both found, take whichever comes first
        if string_answer is None:
            string_answer = "Tau"
        else:
            rho_pos = text_lower.index("rho")
            tau_pos = text_lower.index("tau")
            string_answer = "Rho" if rho_pos < tau_pos else "Tau"

    # Determine correctness
    answer = token_answer or string_answer
    if answer is None:
        return {"answer": None, "correct": False, "no_answer": True,
                "token_answer": None, "string_answer": None, "agreement": True}

    correct = (answer == valid_token)
    agreement = (token_answer == string_answer) or (token_answer is None) or (string_answer is None)

    return {
        "answer": answer,
        "correct": correct,
        "no_answer": False,
        "token_answer": token_answer,
        "string_answer": string_answer,
        "agreement": agreement,
    }
```

### Anti-Patterns to Avoid

- **Batching multiple probe points:** Each probe point has a different sequence length. While theoretically batchable with left-padding, the varying lengths and KV cache management make this error-prone. Process sequentially -- the pilot is only 1000 probes.
- **Using nnsight for generation:** The project established that `model._model.generate()` (raw HF model) is the correct pattern. Do not use `model.generate()` through nnsight's wrapper.
- **Storing full generated text:** The decision explicitly says NOT to store generated text. Only store metrics (correct, no_answer, rho_prob, tau_prob).
- **Using sampling (do_sample=True):** For the force-answer experiment, use greedy decoding (do_sample=False) for reproducibility. The original trace generation used sampling, but the forced answer should be deterministic.

## Common Pitfalls

### Pitfall 1: Rho is Two Tokens, Tau is One Token
**What goes wrong:** Treating Rho and Tau symmetrically in token-level matching fails because "Rho" tokenizes to `[49, 6161]` ("R" + "ho") while "Tau" tokenizes to `[92713]` (single token).
**Why it happens:** The Qwen3 tokenizer has "Tau" as a single vocabulary entry but splits "Rho" into subwords.
**How to avoid:** Token-level matching must check for the two-token sequence `[49, 6161]` for Rho, not a single token.
**Warning signs:** Rho is never detected at the token level, only at the string level.
**Verified:** YES -- confirmed with `tokenizer.encode('Rho') -> [49, 6161]` and `tokenizer.encode('Tau') -> [92713]`.

### Pitfall 2: model.generate() Requires Full input_ids Even with past_key_values
**What goes wrong:** Passing only the new tokens (e.g., `</think>\n`) as input_ids when past_key_values is set causes incorrect generation.
**Why it happens:** In transformers 5.0, `model.generate()` handles the cache-vs-input coordination internally. It expects the FULL input_ids sequence and internally determines which tokens have cached KV values.
**How to avoid:** Always pass full input_ids (prefix + thinking tokens up to probe point + close tokens). The model will figure out that only the close tokens need processing.
**Warning signs:** Generated text is garbage or unrelated to the prompt.
**Verified:** YES -- confirmed from official HuggingFace prefix caching examples in docs.

### Pitfall 3: Attention Mask Must Match Full Sequence Length
**What goes wrong:** When using past_key_values, the attention mask must cover the entire sequence (cached + new tokens), not just the new tokens.
**Why it happens:** Attention computations need to know which positions to attend to across the full context.
**How to avoid:** `attention_mask = torch.ones(1, len(full_input_ids), device=device)` -- all ones since no padding.
**Warning signs:** Shape mismatch errors or incorrect attention patterns.

### Pitfall 4: Probe Position 0 (Very Beginning) May Be Meaningless
**What goes wrong:** Probing at position 0 means the model has seen `<think>` but zero thinking tokens. The "answer" is essentially random.
**Why it happens:** Even spacing of 20 points includes the very start of thinking.
**How to avoid:** This is actually fine data-wise -- it establishes a baseline. But don't be surprised if position 0 shows ~50% accuracy (chance).

### Pitfall 5: Very Short Traces with 20 Probe Points
**What goes wrong:** If a trace has only 50 thinking tokens, 20 evenly-spaced points means probes every 2.5 tokens -- essentially every position.
**Why it happens:** No minimum spacing between probe points is enforced.
**How to avoid:** Impose a minimum spacing of ~5 tokens between probe points. If the trace is too short for 20 points at that spacing, use fewer points (e.g., `num_probes = min(20, think_length // 5)`).
**Recommendation:** Set minimum spacing to 5 tokens. For a 50-token thinking block, this gives 10 probes. For a 100-token block, 20 probes. For 800+ token blocks (the majority), 20 probes are comfortably spaced.

### Pitfall 6: Config A vs Config B Label Mapping
**What goes wrong:** Forgetting that "Rho" means "correct" in config A but "incorrect" in config B.
**Why it happens:** The swapped-label protocol assigns different meanings to Rho/Tau per config.
**How to avoid:** Always read `valid_token` and `invalid_token` from trace metadata, never hardcode the mapping. The `ground_truth` field + `valid_token` field together determine the expected answer.
**Example:**
```python
# From trace metadata:
# ground_truth = "Yes" -> model should output valid_token
# ground_truth = "No"  -> model should output invalid_token
expected_token = meta['valid_token'] if meta['ground_truth'] == 'Yes' else meta['invalid_token']
```

### Pitfall 7: `</think>` + `\n` vs `</think>` + `\n\n`
**What goes wrong:** In real traces, the model outputs `\n\n` (token 271) after `</think>`, but when force-closing, the decision says to use `</think>\n`.
**Why it happens:** The model naturally produces a double newline, but `</think>\n` is a single newline.
**How to avoid:** Use `[151668, 198]` (`</think>` + `\n`) as specified in the decision. The model will adapt to either. Using `\n` (single) is fine -- it signals the transition out of thinking mode.
**Verified:** `tokenizer.encode('</think>\n') -> [151668, 198]`.

### Loading and Filtering Traces
```python
# Source: Verified against actual trace files at /mnt/data/aahmad/data/traces/valid/
import json
import os
import random

def load_traces_for_experiment(traces_dir, n_per_dataset=17, n_correct=40, n_incorrect=10, seed=137):
    """Load and filter traces for the force-answer experiment.

    Returns list of dicts with trace data + metadata.
    """
    rng = random.Random(seed)
    all_traces = []

    for dataset in ['gsm_symbolic', 'folio', 'strategyqa']:
        ds_dir = os.path.join(traces_dir, 'valid', dataset)
        traces = []
        for problem_dir in os.listdir(ds_dir):
            trace_path = os.path.join(ds_dir, problem_dir, 'trace_00.json')
            if not os.path.exists(trace_path):
                continue
            with open(trace_path) as f:
                data = json.load(f)
            meta = data['metadata']
            if not meta['has_think'] or meta['num_think_blocks'] != 1:
                continue

            # Determine correctness from generated output
            think_end = meta['think_boundaries'][0][1]
            token_ids = data['token_ids']
            valid_token = meta.get('valid_token', '')
            expected = valid_token if meta['ground_truth'] == 'Yes' else meta.get('invalid_token', '')
            text_after_think = data['generated_text'][data['generated_text'].rfind('</think>')+8:]
            is_correct = expected.lower() in text_after_think.lower() if expected else False

            traces.append({
                'trace_path': trace_path,
                'token_ids': data['token_ids'],
                'metadata': meta,
                'is_correct': is_correct,
                'dataset': dataset,
            })

        # Sample from this dataset
        correct = [t for t in traces if t['is_correct']]
        incorrect = [t for t in traces if not t['is_correct']]
        rng.shuffle(correct)
        rng.shuffle(incorrect)

        # Proportional allocation of correct/incorrect within dataset
        n_correct_ds = round(n_correct * n_per_dataset / 50)
        n_incorrect_ds = n_per_dataset - n_correct_ds

        selected = correct[:n_correct_ds] + incorrect[:n_incorrect_ds]
        all_traces.extend(selected)

    return all_traces
```

### Computing Probe Positions
```python
import numpy as np

def compute_probe_positions(think_length, num_probes=20, min_spacing=5):
    """Compute evenly-spaced probe positions within a thinking block.

    Args:
        think_length: number of content tokens between <think> and </think>
        num_probes: desired number of probe points
        min_spacing: minimum token spacing between probes

    Returns:
        list of int positions (0-indexed relative to think content start)
    """
    # Adjust num_probes if trace is too short for desired spacing
    max_probes = max(1, think_length // min_spacing)
    actual_probes = min(num_probes, max_probes)

    if actual_probes <= 1:
        return [think_length // 2]

    # Evenly space from 0 to think_length (exclusive)
    # Use linspace to get even distribution
    positions = np.linspace(0, think_length - 1, actual_probes, dtype=int)
    # Remove duplicates that may arise from rounding
    positions = sorted(set(positions.tolist()))

    return positions
```

### Extracting Logit Probabilities for Rho/Tau
```python
import torch

RHO_FIRST_TOKEN_ID = 49    # "R" (first token of "Rho")
TAU_TOKEN_ID = 92713        # "Tau" (single token)

def extract_rho_tau_probs(first_logits, device='cpu'):
    """Extract Rho and Tau probabilities from the first generation step logits.

    Args:
        first_logits: logits tensor of shape [vocab_size] at the first generated position

    Returns:
        dict with rho_prob, tau_prob (float values between 0 and 1)
    """
    probs = torch.softmax(first_logits.float(), dim=-1)

    # Tau probability: single token
    tau_prob = probs[TAU_TOKEN_ID].item()

    # Rho probability: first token "R" (token 49)
    # Note: The full "Rho" requires [49, 6161], but the probability of "Rho"
    # as an answer is best approximated by P(first token = "R"|context).
    # If the model "wants" to say Rho, it will produce token 49 first.
    rho_prob = probs[RHO_FIRST_TOKEN_ID].item()

    return {'rho_prob': float(rho_prob), 'tau_prob': float(tau_prob)}
```

### Plotting Accuracy and Probability Curves
```python
import matplotlib.pyplot as plt
import matplotlib
import pandas as pd

# Recommended style settings
matplotlib.rcParams.update({
    'figure.figsize': (14, 5),
    'font.size': 12,
    'axes.labelsize': 13,
    'axes.titlesize': 14,
    'legend.fontsize': 11,
    'figure.dpi': 150,
    'savefig.dpi': 200,
    'savefig.bbox_inches': 'tight',
})

# Color palette: colorblind-friendly
DATASET_COLORS = {
    'gsm_symbolic': '#0077BB',   # blue
    'folio': '#EE7733',          # orange
    'strategyqa': '#009988',     # teal
}

def plot_transition_curves(df, output_dir):
    """Generate accuracy and probability plots side-by-side.

    Args:
        df: DataFrame with columns: normalized_position, correct,
            correct_token_prob, dataset
        output_dir: directory to save PNG files
    """
    fig, (ax1, ax2) = plt.subplots(1, 2, figsize=(14, 5))

    # Left: Accuracy vs position
    for dataset, color in DATASET_COLORS.items():
        subset = df[df['dataset'] == dataset]
        if subset.empty:
            continue
        # Bin positions for smoother curves
        grouped = subset.groupby('normalized_position')['correct'].agg(['mean', 'count'])
        # 95% CI: mean +/- 1.96 * sqrt(p*(1-p)/n)
        grouped['ci'] = 1.96 * ((grouped['mean'] * (1 - grouped['mean'])) / grouped['count']).pow(0.5)

        ax1.plot(grouped.index, grouped['mean'], color=color, label=dataset, linewidth=2)
        ax1.fill_between(grouped.index,
                         (grouped['mean'] - grouped['ci']).clip(0, 1),
                         (grouped['mean'] + grouped['ci']).clip(0, 1),
                         color=color, alpha=0.15)

    ax1.set_xlabel('Normalized Position in Thinking Block')
    ax1.set_ylabel('Accuracy')
    ax1.set_title('Force-Answer Accuracy vs Thinking Position')
    ax1.set_xlim(0, 1)
    ax1.set_ylim(-0.05, 1.05)
    ax1.legend()
    ax1.grid(True, alpha=0.3)

    # Right: Probability vs position
    for dataset, color in DATASET_COLORS.items():
        subset = df[df['dataset'] == dataset]
        if subset.empty:
            continue
        grouped = subset.groupby('normalized_position')['correct_token_prob'].agg(['mean', 'sem'])
        grouped['ci'] = 1.96 * grouped['sem']

        ax2.plot(grouped.index, grouped['mean'], color=color, label=dataset, linewidth=2)
        ax2.fill_between(grouped.index,
                         (grouped['mean'] - grouped['ci']).clip(0, 1),
                         (grouped['mean'] + grouped['ci']).clip(0, 1),
                         color=color, alpha=0.15)

    ax2.set_xlabel('Normalized Position in Thinking Block')
    ax2.set_ylabel('P(correct answer token)')
    ax2.set_title('Correct Answer Token Probability vs Thinking Position')
    ax2.set_xlim(0, 1)
    ax2.set_ylim(-0.05, 1.05)
    ax2.legend()
    ax2.grid(True, alpha=0.3)

    plt.tight_layout()
    plt.savefig(os.path.join(output_dir, 'transition_curves.png'))
    plt.close()
```

## Discretionary Recommendations

### CSV vs Parquet
**Recommendation: Parquet.** Parquet preserves types (bool stays bool, float stays float), is more compact, and loads faster with pandas. CSV requires type inference and can mangle booleans. Parquet is trivially readable with `pd.read_parquet()`.

### model.generate() vs Manual Token-by-Token
**Recommendation: `model.generate()` with `return_dict_in_generate=True, output_logits=True`.** This gives us both the generated sequence AND the logits at each step. The logits from step 0 (first token after `</think>\n`) are what we need for Rho/Tau probability extraction. Manual generation would require implementing the sampling loop ourselves -- unnecessary complexity.

### Very Short Traces
**Recommendation: Minimum spacing of 5 tokens between probes.** If `think_length < 20 * 5 = 100`, reduce probe count to `think_length // 5`. This prevents meaningless probes at nearly identical positions. The normalized position (0-1 scale) still works correctly regardless of probe count.

### Plot Style and Colors
**Recommendation:** Colorblind-friendly palette (Blue/Orange/Teal for 3 datasets), as shown in the code example above. White background, light grid, 150 DPI for screen display, 200 DPI for saved PNGs. Side-by-side layout (accuracy + probability) in a single figure.

## Open Questions

1. **Greedy vs temperature for forced answer:**
   - What we know: Original traces used temperature=0.6 + top_p=0.95. Force-answer should probably use greedy (do_sample=False) for reproducibility.
   - What's unclear: Does the model behave differently under greedy vs. sampled decoding when forced to answer early? Greedy is deterministic which is better for this experiment.
   - Recommendation: Use greedy (do_sample=False). The decision says "freely generate" but greedy is safest for reproducibility.

2. **Which trace per problem to use:**
   - What we know: Each problem has 3 traces (trace_00, trace_01, trace_02).
   - What's unclear: Are the traces different enough to matter?
   - Recommendation: Use trace_00 only for the pilot. 50 traces x 20 probes = 1000 data points is sufficient for visual exploration.

3. **KV cache with nnsight wrapper:**
   - What we know: `model._model` provides the raw HuggingFace model. `model._model.generate()` is the established generation pattern.
   - What's unclear: Whether `model._model.forward()` (for prefill) returns `past_key_values` correctly when `DynamicCache` is passed.
   - Recommendation: Test with one trace first before running the full experiment. The simple approach (Pattern 2) is the fallback.
