## Summary

Phase 2.3 extends Phase 2.2's force-answer probing from a single trace per problem to 20 traces per problem (different random seeds), then analyzes whether the model's transition from "not knowing" to "knowing" occurs at a consistent normalized position across seeds. This requires three major components: (1) generating 17 new traces per problem for the ~41 originally-correct problems from the Phase 2.2 selection, (2) running force-answer probing on all 20 traces per problem, and (3) producing per-problem visualizations and cross-seed agreement metrics.

The infrastructure for all three components already exists in the codebase. Trace generation uses `scripts/generate_traces.py` with `derive_trace_seed()` for deterministic seeding. Force-answer probing uses `scripts/force_answer_experiment.py` with KV-cache-efficient truncation. Visualization follows the patterns in `scripts/plot_force_answer.py`. The new work is primarily integration: a generation script for targeted problems (not the full dataset), an adapted probing script that handles multiple seeds per problem, and new analysis/visualization logic.

**Primary recommendation:** Build three scripts: (1) a targeted trace generation script that generates 17 new traces for the selected ~41 problems by reusing the verification_prompt stored in existing trace metadata, (2) an adapted force-answer probing script that processes all 20 seeds per problem and outputs a seed-aware parquet, (3) a visualization + metrics script that produces per-problem PNGs and aggregate cross-seed agreement statistics.

### Pattern 1: Targeted Trace Generation via Stored Prompts
**What:** Instead of re-loading datasets and re-building prompts, extract the `verification_prompt` from an existing trace's metadata and use it directly for new trace generation.
**Why:** The existing traces at `$DATA_DIR/traces/valid/{dataset}/{problem_id}/trace_00.json` contain the full `verification_prompt` in metadata. Reusing it guarantees prompt identity across seeds and avoids re-running dataset loading logic (which involves HuggingFace downloads and random sampling).
**How it works:**
1. For each selected problem_id, read `trace_00.json` metadata to get `verification_prompt`, `dataset_name`, `ground_truth`, and all other metadata fields.
2. For trace indices 3-19 (0-2 already exist), call `derive_trace_seed(problem_id, trace_index)` to get a deterministic seed.
3. Call `set_seed(seed)` then `generate_trace(model, tokenizer, prompt, max_new_tokens=4096)`.
4. Parse think boundaries, build trace data dict, route to valid/ or failed/.
5. This reuses the `generate_traces.py` worker pattern but operates on a targeted problem list rather than the full dataset.

**Confidence:** HIGH -- verified that `verification_prompt` is stored in trace metadata (confirmed by inspecting actual trace JSON files).

### Pattern 2: Seed-Aware Probing Results
**What:** Extend the Phase 2.2 probing to produce results tagged with `seed_index` and `trace_index` columns, so downstream analysis can group by (problem_id, seed_index).
**Why:** Phase 2.2's `force_answer_experiment.py` outputs one row per (trace_id, probe_position). For Phase 2.3, each problem_id has 20 traces, so the parquet needs `seed_index` (0-19) and `trace_index` (0-19) to distinguish them.
**How:** Adapt `probe_trace()` to add `seed_index` and `trace_index` to each result row. The `trace_id` column should remain `problem_id` (the problem, not the seed-specific variant), so per-problem grouping works naturally.

**Confidence:** HIGH -- straightforward extension of existing code.

### Pattern 3: Per-Problem Two-Panel Visualization
**What:** For each problem, produce a PNG with two side-by-side panels (accuracy left, P(correct) right). Each panel shows 20 faint individual seed curves plus a bold mean curve.
**Why:** This is the locked decision from CONTEXT.md. The visual reveals whether seeds agree on transition timing.
**How:**
- For each problem_id, filter the results parquet to that problem's rows.
- Group by (seed_index, normalized_position) to get per-seed curves.
- Interpolate all seeds to a common set of normalized positions (different seeds may have different think_lengths and thus different exact normalized positions).
- Plot each seed as a faint line (alpha=0.15-0.2), plot the mean across seeds as a bold line.
- Shared x-axis: 0 to 1. Y-axis: 0 to 1 for both panels.

**Confidence:** HIGH -- standard matplotlib pattern.

### Pattern 4: Cross-Seed Agreement Metrics
**What:** Three quantitative metrics per problem measuring how consistently seeds agree on transition dynamics.
**Why:** Locked decision from CONTEXT.md -- these specific three metrics were chosen.

1. **Mean accuracy curve sharpness (max slope):**
   - Compute the mean accuracy curve across seeds (interpolated to common positions).
   - Take the max of the finite differences: `max(np.diff(mean_accuracy) / np.diff(positions))`.
   - Higher = sharper transition. Near 0 = flat curve (always right or always wrong).

2. **Position-wise variance:**
   - At each normalized position, compute variance of correctness (0/1) across seeds.
   - Report mean variance across positions. Low = seeds agree at most positions.
   - Also useful: max variance (indicates the position of most disagreement).

3. **Pairwise Spearman correlation:**
   - For each pair of seeds (190 pairs for 20 seeds), compute Spearman correlation between their accuracy curves (interpolated to common positions).
   - Report mean pairwise correlation per problem.
   - Use `scipy.stats.spearmanr`.
   - High correlation (>0.7) = seeds show consistent transition dynamics.

**Confidence:** HIGH -- standard statistical operations, scipy.stats.spearmanr verified available.

## Common Pitfalls

### Pitfall 1: Inconsistent Normalized Positions Across Seeds
**What goes wrong:** Different seeds produce traces with different think_lengths. When you compute `normalized_position = pos / (think_length - 1)`, each seed's ~20 probe positions land at slightly different normalized positions (e.g., seed 1 at 0.05, 0.10, ...; seed 2 at 0.04, 0.09, ...).
**Why it happens:** Think length varies per seed because the model generates different amounts of reasoning text.
**How to avoid:** When computing per-problem mean curves and cross-seed metrics, interpolate all seeds to a common grid of normalized positions. Use `np.interp()` with a shared grid (e.g., `np.linspace(0, 1, 21)`). This is the standard approach for aligning curves with different x-spacing.
**Warning signs:** If you compute mean accuracy by just averaging the dataframe column at each `normalized_position`, you'll get NaN for most positions because no two seeds share exact positions. The binning approach from `plot_force_answer.py` (using `pd.cut` into 25 bins) is an alternative, but interpolation is cleaner for per-problem analysis.

### Pitfall 2: Insufficient Seeds After Filtering
**What goes wrong:** Some of the 20 generated traces may have multi-think-block or no-think-block, reducing the effective seed count below 20 for some problems.
**Why it happens:** The model occasionally generates malformed traces -- multiple `<think>` blocks, no `<think>` block, or premature closure.
**How to avoid:** Generate all 20 trace indices (0-19). After generation, filter to single-think-block traces. Log how many seeds passed the filter per problem. For metrics, require a minimum seed count (e.g., >= 10) and flag problems with fewer. In the per-problem plot, note the actual seed count in the title.
**Warning signs:** If any problem has fewer than 5 valid seeds, the cross-seed metrics become unreliable. Based on Phase 2 data, the single-think-block rate is very high (all 800 traced problems in the valid directory passed this filter), so this is unlikely to be a major issue.

### Pitfall 3: Generation Script Not Getting Same Prompt
**What goes wrong:** If you re-run the dataset loading and prompt construction, the prompts might differ (e.g., distractor numbers change due to RNG state, or dataset loading order differs).
**Why it happens:** `load_gsm_symbolic_contamination()` uses an RNG to generate distractors, and the exact sequence depends on call order.
**How to avoid:** Extract the `verification_prompt` from existing `trace_00.json` metadata rather than reconstructing it. This guarantees byte-identical prompts across all seeds for the same problem.
**Warning signs:** If generated traces give systematically different answers from the existing traces at the same probe position, the prompts may not match.

### Pitfall 4: Trace Index Collision
**What goes wrong:** Trying to generate traces with indices 0-2 that already exist, or using wrong indices that don't align with `derive_trace_seed()`.
**Why it happens:** The existing traces use indices 0, 1, 2. New traces should use indices 3-19.
**How to avoid:** The generation script should use `trace_index` values 3-19 (17 new traces). `derive_trace_seed(problem_id, trace_index)` automatically produces a unique seed for each index. The existing trace files (trace_00.json through trace_02.json) are left untouched and reused as seeds 0-2. The file-based resume in `generate_traces.py` already handles this: `if os.path.exists(valid_path) or os.path.exists(failed_path): skipped_count += 1; continue`.
**Warning signs:** Files named trace_03.json through trace_19.json should appear in the problem directories after generation.

### Pitfall 5: Memory Pressure with 20-Seed Probing
**What goes wrong:** Probing 41 problems x 20 seeds x 20 probes = 16,400 generate() calls may cause GPU OOM if not properly managed.
**Why it happens:** Each generate() call allocates KV cache memory. If torch.cuda.empty_cache() is not called between traces, memory fragments accumulate.
**How to avoid:** Call `torch.cuda.empty_cache()` after each trace (already done in Phase 2.2's worker). Use 4 GPUs to distribute the load (~4100 calls per GPU). The KV-cache approach with descending probe order minimizes memory allocation per trace. Total estimated time: ~20-30 minutes on 4 GPUs.
**Warning signs:** OOM errors after processing many traces. Monitor GPU memory usage.

### Pitfall 6: Parquet Column Schema Mismatch
**What goes wrong:** The cross-seed experiment parquet needs additional columns (seed_index, trace_index) not present in Phase 2.2's schema. If code assumes the old schema, it will break.
**How to avoid:** Define the full column set upfront. Include all Phase 2.2 columns PLUS seed_index (int) and trace_index (int). The `trace_id` column should be the `problem_id` (same across seeds for a given problem), not the seed-specific identifier.

def plot_problem_seeds(problem_id, df_problem, output_dir):
    """Create two-panel plot for a single problem with 20 seed curves."""
    fig, (ax_acc, ax_prob) = plt.subplots(1, 2, figsize=(14, 5))

    # Common interpolation grid
    grid = np.linspace(0, 1, 21)

    # Collect interpolated curves per seed
    acc_curves = []
    prob_curves = []
    n_seeds = df_problem["seed_index"].nunique()

    for seed_idx in sorted(df_problem["seed_index"].unique()):
        seed_df = df_problem[df_problem["seed_index"] == seed_idx].sort_values("normalized_position")
        x = seed_df["normalized_position"].values
        acc = seed_df["correct"].astype(float).values
        prob = seed_df["correct_token_prob"].values

        acc_interp = np.interp(grid, x, acc)
        prob_interp = np.interp(grid, x, prob)
        acc_curves.append(acc_interp)
        prob_curves.append(prob_interp)

        # Faint individual curves
        ax_acc.plot(grid, acc_interp, color="#0077BB", alpha=0.15, linewidth=0.8)
        ax_prob.plot(grid, prob_interp, color="#EE7733", alpha=0.15, linewidth=0.8)

    # Bold mean curves
    mean_acc = np.mean(acc_curves, axis=0)
    mean_prob = np.mean(prob_curves, axis=0)
    ax_acc.plot(grid, mean_acc, color="#0077BB", linewidth=2.5, label=f"Mean (n={n_seeds})")
    ax_prob.plot(grid, mean_prob, color="#EE7733", linewidth=2.5, label=f"Mean (n={n_seeds})")

    # Styling
    for ax, title, ylabel in [
        (ax_acc, "Binary Accuracy", "Accuracy"),
        (ax_prob, "P(correct token)", "Probability"),
    ]:
        ax.set_xlabel("Normalized Position")
        ax.set_ylabel(ylabel)
        ax.set_xlim(0, 1)
        ax.set_ylim(-0.02, 1.02)
        ax.set_title(title)
        ax.legend()
        ax.grid(True, alpha=0.3)
        ax.axhline(0.5, color="gray", linestyle=":", alpha=0.5)

    fig.suptitle(problem_id, fontsize=11, y=1.02)
    plt.tight_layout()
    fig.savefig(os.path.join(output_dir, f"{problem_id}.png"), bbox_inches="tight")
    plt.close(fig)

### Example 4: Cross-Seed Agreement Metrics
```python
from scipy.stats import spearmanr

def compute_agreement_metrics(df_problem, grid=None):
    """Compute cross-seed agreement metrics for a single problem."""
    if grid is None:
        grid = np.linspace(0, 1, 21)

    # Interpolate each seed's accuracy curve to common grid
    acc_curves = []
    for seed_idx in sorted(df_problem["seed_index"].unique()):
        seed_df = df_problem[df_problem["seed_index"] == seed_idx].sort_values("normalized_position")
        x = seed_df["normalized_position"].values
        acc = seed_df["correct"].astype(float).values
        acc_interp = np.interp(grid, x, acc)
        acc_curves.append(acc_interp)

    acc_matrix = np.array(acc_curves)  # shape: (n_seeds, n_positions)
    mean_acc = acc_matrix.mean(axis=0)

    # 1. Sharpness: max slope of mean accuracy curve
    diffs = np.diff(mean_acc) / np.diff(grid)
    sharpness = float(np.max(np.abs(diffs)))

    # 2. Position-wise variance: variance of correctness across seeds at each position
    pos_variance = acc_matrix.var(axis=0)  # shape: (n_positions,)
    mean_pos_variance = float(pos_variance.mean())
    max_pos_variance = float(pos_variance.max())

    # 3. Pairwise Spearman correlation
    n_seeds = len(acc_curves)
    correlations = []
    for i in range(n_seeds):
        for j in range(i + 1, n_seeds):
            rho, _ = spearmanr(acc_curves[i], acc_curves[j])
            if not np.isnan(rho):
                correlations.append(rho)
    mean_spearman = float(np.mean(correlations)) if correlations else float("nan")

    return {
        "sharpness": sharpness,
        "mean_pos_variance": mean_pos_variance,
        "max_pos_variance": max_pos_variance,
        "mean_pairwise_spearman": mean_spearman,
        "n_seeds": n_seeds,
    }
```

## Discretion Recommendations

These are areas where CONTEXT.md grants Claude's discretion. Based on research, here are the recommendations:

### 1. Trace Generation Approach
**Recommendation:** Create a new standalone script `scripts/generate_seed_traces.py` rather than modifying `scripts/generate_traces.py`.

**Rationale:**
- `generate_traces.py` is tightly coupled to the full dataset loading pipeline (calls `load_gsm_symbolic_contamination()`, `load_folio()`, etc.) and the swapped-label expansion logic. Adapting it for targeted generation of 17 specific trace indices for 41 specific problems would require significant conditional logic.
- A standalone script that reads problem metadata from existing trace_00.json files (Pattern 1 above) is cleaner, simpler, and avoids any risk of re-running dataset loading that might produce different prompts.
- The standalone script reuses `src.model.generate_trace()`, `src.storage.derive_trace_seed()`, `src.storage.write_trace_json()`, `src.multiprocess.run_parallel_isolated()`, and `src.tokens.parse_think_boundaries()` -- all the real work is done by existing infrastructure.
- The problem list can be hardcoded or derived from the Phase 2.2 selection logic (reproduce it deterministically).

### 2. Handling Multi-Think-Block or No-Think Seeds
**Recommendation:** Skip those seeds entirely. Log how many seeds were skipped per problem. In the per-problem plot title, show the actual seed count (e.g., "Problem X (18/20 seeds)"). In the metrics parquet, record `n_seeds` per problem.

**Rationale:**
- Based on the existing data, the single-think-block rate is essentially 100% (all 800 problems in valid/ have this). Multi-think-block traces are rare with Qwen3-8B at these generation parameters.
- Adding complexity to handle partial traces is not worth it for the expected number of affected seeds (likely 0-2 across all problems).
- If a problem has fewer than 5 valid seeds, flag it in the metrics output but still include it.

### 3. Colors/Styling for Per-Problem Plots
**Recommendation:** Use the existing colorblind-friendly palette from `plot_force_answer.py`:
- Accuracy panel: blue (#0077BB) for individual seeds (alpha=0.15) and bold mean
- Probability panel: orange (#EE7733) for individual seeds (alpha=0.15) and bold mean
- Gray dashed line at 0.5 (chance level)
- White background, light grid, 200 DPI
- Problem ID as figure suptitle
- Seed count shown in legend: "Mean (n=20)"

### 4. Summary Plot Design
**Recommendation:** Two summary plots:

1. **Sharpness histogram:** Distribution of max-slope values across problems. Bimodal distribution would suggest two categories of problems (sharp vs gradual transitions). X-axis: sharpness value. Y-axis: count. 15-20 bins.

2. **Agreement scatter:** Mean pairwise Spearman correlation (x-axis) vs mean position-wise variance (y-axis) for each problem. Color by dataset. This shows the relationship between two different agreement measures and whether certain datasets cluster differently.

### 5. Script Architecture: Reuse vs New
**Recommendation:** Create a new probing script `scripts/cross_seed_experiment.py` that imports functions from `scripts/force_answer_experiment.py` rather than modifying it.

**Rationale:**
- The core probing functions (`probe_trace()`, `extract_answer()`, `extract_rho_tau_probs()`, `compute_probe_positions()`) are reusable as-is. Import them directly.
- The trace loading and selection logic is different: Phase 2.2 loads one trace per problem from 51 problems; Phase 2.3 loads 20 traces per problem from 41 problems. This is different enough to warrant a new loading function.
- The worker function needs a different signature to handle seed-awareness (adding seed_index/trace_index to results).
- The main() function orchestration is different (merge shards, then hand off to analysis).
- A new config file `configs/cross_seed.yaml` keeps the experiment-specific parameters separate.

## Key Implementation Details

### Problem Selection: Reproducing Phase 2.2's ~41 Originally-Correct Problems
The Phase 2.2 selection uses `random.Random(137)` with proportional allocation. Based on the actual data:
- Total selected: 51 problems
- Originally correct: 41 (22 GSM-Symbolic, 10 FOLIO, 9 StrategyQA)
- Originally incorrect: 10 (excluded from Phase 2.3)

The selection is deterministic given the same data on disk, so it can be reproduced by re-running `load_traces_for_experiment()` from `force_answer_experiment.py` and filtering to `is_correct=True`. The selected problem IDs are stable as long as the trace data does not change.

### Trace Index Mapping to Seed Index
For a given problem_id:
- trace_index 0, 1, 2: existing traces (seed 0, 1, 2)
- trace_index 3-19: new traces (seed 3-19)

The "seed_index" in the output parquet should map 0-19 for readability, corresponding to trace_index 0-19. Each has a unique deterministic seed from `derive_trace_seed(problem_id, trace_index)`.

### Interpolation for Cross-Seed Comparison
Different seeds produce different think_lengths, meaning probe positions land at different normalized positions. For computing metrics and plotting mean curves, interpolate all seeds to a common grid using `np.interp()`:

```python
grid = np.linspace(0, 1, 21)  # 21 points for 5% spacing
for seed in seeds:
    interp_acc = np.interp(grid, seed_positions, seed_accuracy)
```

The 21-point grid (0.00, 0.05, ..., 1.00) provides sufficient resolution since each seed only has ~20 raw probe points anyway.
