**Step A: Create `configs/cross_seed.yaml`**

Config for the cross-seed experiment. Merges on top of base.yaml.

```yaml
# Cross-seed transition consistency experiment config
# Merges on top of base.yaml via load_config("configs/cross_seed.yaml")

# Inherit generation parameters from base.yaml (temperature=0.6, top_p=0.95, top_k=20)
model:
  max_new_tokens: 4096

cross_seed:
  # Trace generation
  new_trace_start: 3          # first new trace index (0-2 already exist)
  new_trace_end: 20           # exclusive end (generates indices 3-19)
  total_seeds: 20             # total seeds per problem (0-19)
  min_valid_seeds: 10         # minimum seeds to include problem in metrics

  # Probing (same parameters as Phase 2.2)
  num_probes: 20
  min_probe_spacing: 5
  max_new_tokens: 15

  # Selection (reproduces Phase 2.2 selection)
  selection_seed: 137
  n_correct: 40
  n_incorrect: 10
  trace_index: 0              # Phase 2.2 used trace_00 for selection

  # Token IDs (same as Phase 2.2)
  close_token_ids: [151668, 198]
  rho_token_ids: [49, 6161]
  tau_token_id: 92713

  # Interpolation
  interp_grid_points: 21      # np.linspace(0, 1, 21) for cross-seed comparison

paths:
  traces_dir: "${paths.data_dir}/traces"
  output_dir: "${oc.env:EXP_DIR}/force_answer_seeds"

gpus: [0, 1, 2, 3]
```

**Step B: Create `scripts/generate_seed_traces.py`**

A standalone script that generates 17 new traces per ~41 originally-correct problems. Structure:

**Imports:**
- `import gc, json, logging, os, time`
- `import torch`
- `from dotenv import load_dotenv` (call `load_dotenv()` immediately)
- `from src.config import load_config`
- `from src.model import generate_trace, load_model`
- `from src.multiprocess import run_parallel_isolated`
- `from src.storage import derive_trace_seed, get_trace_json_path, get_failed_trace_json_path, write_trace_json`
- `from src.tokens import parse_think_boundaries`
- `from src.utils import set_seed, setup_logging`
- Import `load_traces_for_experiment` from `scripts.force_answer_experiment` (use sys.path insertion to make scripts importable: `sys.path.insert(0, os.path.dirname(os.path.dirname(os.path.abspath(__file__))))`)

**Function: `select_correct_problems(traces_dir, cfg)`**
- Call `load_traces_for_experiment(traces_dir, cfg)` -- this uses the Phase 2.2 selection logic (same seed=137, same proportional allocation). But to call this function, the config needs `force_answer` section. To avoid coupling, instead REPRODUCE the selection logic inline:
  - Actually, the simplest correct approach: call `load_traces_for_experiment()` with a config that has the `force_answer` section. The cross_seed.yaml config should have this data in its `cross_seed` section. Create a lightweight shim:
    - Build a minimal config dict: `fa_cfg = OmegaConf.create({"force_answer": {"trace_index": cfg.cross_seed.trace_index, "n_correct": cfg.cross_seed.n_correct, "n_incorrect": cfg.cross_seed.n_incorrect, "selection_seed": cfg.cross_seed.selection_seed, "num_probes": 20, "min_probe_spacing": 5, "max_new_tokens": 15}})`
    - Then call: `all_selected = load_traces_for_experiment(traces_dir, fa_cfg)`
    - Filter to `is_correct=True` only: `correct_problems = [t for t in all_selected if t["is_correct"]]`
    - Return a 2-tuple `(all_selected, correct_only)` -- `all_selected` is the full ~51 list, `correct_only` is the sublist with `is_correct=True` (~41 problems). Each dict has trace_path, token_ids, metadata, is_correct, dataset.
- Alternative (PREFERRED for simplicity): Re-implement the selection logic directly. Walk the traces directory exactly as `load_traces_for_experiment` does, apply the same selection with `random.Random(137)`, then filter to correct only. This avoids any import gymnastics.
- DECISION: Re-implement inline for robustness. Copy the core logic from `load_traces_for_experiment()` into a `select_problems()` function that returns a 2-tuple `(all_selected, correct_only)` where `all_selected` is the full ~51-problem list and `correct_only` is the sublist filtered to `is_correct=True` (~41 problems).

**Function: `extract_problem_info(trace_data)`**
- From a trace_data dict (returned by select_problems), extract the fields needed for generation:
  - Read the trace_00.json file at `trace_data["trace_path"]` (already loaded in select_problems)
  - Extract `verification_prompt` from metadata (this is the key field -- reuse the EXACT prompt)
  - Return a dict with: problem_id, dataset_name, verification_prompt, ground_truth, valid_token, invalid_token, prompt_config, label_mapping, is_fresh, question, original_answer, presented_answer

**Function: `seed_generation_worker(rank, gpu_id, items, cfg)`**
Worker function following the project standard signature `(rank, gpu_id, items, cfg)`.
- `setup_logging(f"seed_gen.worker{rank}")`
- `torch.cuda.set_device(gpu_id)`
- Load model: `model, tokenizer = load_model(gpu_id=gpu_id)`
- For each problem_info in items:
  - For trace_index in range(cfg.cross_seed.new_trace_start, cfg.cross_seed.new_trace_end):
    - Compute valid_path and failed_path using `get_trace_json_path()` / `get_failed_trace_json_path()`
    - Resume check: skip if either exists
    - `seed = derive_trace_seed(problem_info["problem_id"], trace_index)`
    - `set_seed(seed)`
    - `output_ids = generate_trace(model, tokenizer, problem_info["verification_prompt"], max_new_tokens=cfg.model.max_new_tokens)`
    - `token_list = output_ids[0].tolist()`
    - `generated_text = tokenizer.decode(token_list, skip_special_tokens=False)`
    - `blocks = parse_think_boundaries(token_list)`
    - `has_think = len(blocks) > 0`
    - Build trace_data dict following the EXACT same schema as generate_traces.py (see lines 131-168 of that script). Include all metadata fields: problem_id, dataset_name, ground_truth, question, original_answer, verification_prompt, presented_answer, trace_index, seed, model_name, max_new_tokens, temperature, top_p, top_k, num_tokens, num_think_blocks, has_think, think_boundaries, timestamp. Also include is_fresh, prompt_config, label_mapping, valid_token, invalid_token from the problem_info.
    - Route to valid/ or failed/ based on has_think
    - `write_trace_json(trace_data, dest_path)`
  - After each problem: `torch.cuda.empty_cache()`
- Cleanup: del model, del tokenizer, gc.collect(), torch.cuda.empty_cache()
- Log summary: generated, skipped, valid, failed counts

**Function: `main()`**
- `main_logger = setup_logging("generate_seed_traces")`
- `cfg = load_config()` (will load base.yaml + cross_seed.yaml)
- `set_seed(cfg.seed)`
- `traces_dir = cfg.paths.traces_dir`
- Call select_problems() to get the ~41 correct problems
- Call extract_problem_info() on each to get generation-ready problem dicts
- Log: total problems, per-dataset counts, expected new traces (N_problems * 17)
- `gpu_ids = list(cfg.gpus)`
- `run_parallel_isolated(seed_generation_worker, problem_list, gpu_ids, cfg)`
- Log completion time and output directory
- Count how many new trace files were actually created (scan the directories)

**Key design points:**
- The `verification_prompt` is extracted from existing trace_00.json, NOT reconstructed (per locked decision and Pitfall 3)
- Trace indices 3-19 are generated; 0-2 are left untouched (per Pitfall 4)
- Uses `run_parallel_isolated` for fault tolerance (per project decision)
- File-based resume: existing files are skipped (idempotent)
- Generation parameters match Phase 2: temperature=0.6, top_p=0.95, top_k=20 (from base.yaml generation section)
